# 日中沉浸式翻译

本 fork 内置日文 → 中文的段落对照翻译，不需要安装浏览器翻译扩展。

## 使用

1. 导入 EPUB、HTMLZ 或 TXT，打开书籍，点击页面顶部显示阅读工具栏。
2. 点击「沉浸式翻译」图标，选择本地服务预设或输入云端地址。
3. 填写模型名称；云端服务通常还需要 API 密钥。
4. 点击「测试连接」。测试只发送 `今日はいい天気ですね。`，不发送书籍。
5. 点击「开启竖排对照」。阅读器切换到竖排，日文原段落后紧跟中文译文，自上而下、从右向左阅读。细线和较淡的字体区分译文。

连续和分页模式均支持。原文的 ruby 注音、强调和链接保留，翻译时去除注音。译文不计入原文字数、阅读统计和书签位置。右下角可查看状态、重试失败请求或关闭翻译；点击状态可重新打开设置。

## 连接模型

| 服务               | API 地址                                       | 模型名称                         | 密钥                 |
| ------------------ | ---------------------------------------------- | -------------------------------- | -------------------- |
| Ollama             | `http://localhost:11434/v1`                    | `ollama list` 中已下载模型的名称 | 通常留空             |
| LM Studio          | `http://localhost:1234/v1`                     | 服务中已加载模型的标识           | 按服务配置填写       |
| 云端或自建兼容服务 | 服务商提供的 HTTPS Base URL，通常以 `/v1` 结尾 | 服务商提供的模型 ID              | 服务商提供的 API Key |

接口使用 `POST /chat/completions`，支持 `messages`、`model`、`stream: false`，从 `choices[0].message.content` 读取译文。也可填写完整的 `/chat/completions` 地址。并非所有模型厂商的专用接口都兼容；非兼容接口需通过用户自行部署的兼容网关接入。

Ollama 和 LM Studio 的兼容格式分别见[Ollama 文档](https://docs.ollama.com/api/openai-compatibility)与[LM Studio 文档](https://lmstudio.ai/docs/developer/openai-compat)。模型不由阅读器下载或启动，请先在本地服务中加载支持日中翻译的模型。

## 浏览器跨域与本地访问

此项目是静态网页，API 请求直接从浏览器发送到你填写的服务地址，未增加中转服务器。

- **Ollama**：如遇跨域错误，将实际阅读器 origin（协议、域名和端口，不含路径）加入 `OLLAMA_ORIGINS` 后重启 Ollama。例如本地开发使用 `http://127.0.0.1:5173`；线上部署使用你自己的 HTTPS origin。无需把 Ollama 开放到公网。Windows 下环境变量的设置方法见 [Ollama FAQ](https://docs.ollama.com/faq)。
- **LM Studio**：在服务设置中允许 CORS。具体设置见 [Server Settings](https://lmstudio.ai/docs/developer/core/server/settings)。仅供个人使用时保持服务监听本机。
- **云端 API**：服务必须允许阅读器 origin 的跨域请求，以及 `Content-Type` 和 `Authorization` 请求头。不支持浏览器直连的云端服务，应使用由你控制、持有服务端密钥的兼容网关。
- HTTPS 网页访问本机 HTTP 服务可能受到浏览器本地网络权限和混合内容策略限制；可在同一台电脑上本地运行阅读器，或使用受信任的 HTTPS 服务。本机以外的 API 地址必须使用 HTTPS。
- 手机中的 `localhost` 指手机自身。若模型运行在另一台电脑，请提供可访问的 HTTPS 兼容地址。

## 数据、缓存和错误

- 默认关闭；每次重新进入阅读页面都需要主动开启。开启期间只处理进入视口的段落，翻页或滚动会继续翻译。长段落分块串行发送，每块最多 1800 个 Unicode 字符。
- 中文支持简体和繁体，可填写人名、术语、文风等翻译偏好。
- API 密钥只保存在当前页面会话内存中，刷新后重新输入。地址、模型名、译文语言和偏好保存在本机浏览器设置中。
- 译文只保存在页面 DOM 和最多 500 段的会话缓存中，不改写原书，不写入导出备份。刷新页面后缓存消失；「清除译文缓存」会关闭翻译并删除当前会话缓存。
- 请求失败时暂停队列，避免不断产生失败请求。更改配置或点击「重试」继续。已完成译文可以继续阅读。
- 每次请求最多等待 120 秒。关闭翻译、离开阅读页或更换章节会取消本地等待；已被服务端接收的任务是否停止以及是否计费由服务决定。
- 这是逐段模型翻译，质量取决于模型能力。长篇上下文、跨段人名一致性和原书特殊布局可能需要手动调整偏好。图片内文字不做 OCR；主要支持标准段落、标题、列表项和叶子 div 的文本。

## 验证

接口测试（Node.js 24）：

```sh
pnpm --dir apps/web test:translation
```

浏览器回归测试：在 `apps/web` 目录运行 `pnpm exec vite --config tests/vite.config.mjs`，打开 `http://127.0.0.1:5174/tests/translation-browser.html`。测试使用模拟响应，不调用真实模型。

实际界面测试可在 `apps/web` 目录运行 `node tests/mock-translation-server.mjs`，向阅读器导入 `tests/日中对照测试.txt`，将 API 地址设为 `http://127.0.0.1:11435/v1`，模型设为 `mock`。测试接口对正文返回固定示例中文，仅用于检查排版和流程，不代表真实翻译质量。测试结束后停止该服务并配置实际模型。
